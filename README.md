# Annual Report RAG Lab｜企业年报问答与证据追溯实践

围绕企业年报中的事实与比较问题，研究证据如何从报告页面进入上下文，并出现在最终引用中。

## 当前公开范围

个人研发工作基于 IlyaRice/RAG-Challenge-2 开展，已完成架构梳理、需求与验收拆解、工具配置及初始代码同步。真实模型适配、自建索引与端到端问答尚待验证。公开版当前提供设计说明和合成 Trace 的引用检查示例，不是已复现成功的冠军系统。

本仓库首版整理于 **2026-11-10**。`demo.py` 和 `sample.json` 是本次公开展示新编写的最小示例，经 AI 辅助生成和本地执行检查，不是历史项目源码的完整抽取，也不代表历史实验结果。仓库不要求 API Key、GPU 或第三方 Python 包。

## 一分钟运行

```bash
python demo.py
python demo.py --self-test
```

要求 Python 3.10+。正常输出包含 `valid: true`、`data_kind: synthetic`；自检覆盖正常记录和四类错误，成功时显示 `5 checks passed`。示例只处理随仓库提供的固定结构；不是面向任意外部 JSON 的完备输入校验服务。

对合成执行记录检查：引用是否来自本次上下文、引用页是否在已召回集合中、建库和查询嵌入身份是否一致。它不是检索器、生成模型或幻觉检测器。

## 研发架构与设计取舍

下图描述研发项目的职责划分，不表示全部代码已在公开版提供。

```text
PDF → 解析 → 分块 → 嵌入与索引
问题 → 公司路由 → 召回 → 父页面上下文 / 重排 → 结构化回答与引用
                         └──────── 运行 Trace 与证据检查 ────────┘
```

- 区分继承的开源实现、本人复现准备和后续想法；上游成绩不作为个人实验成绩。
- 换嵌入模型时同时核对建库端和查询端的维度、归一化与模型身份，并重建索引。
- 记录实际送入生成器的上下文；命中某页或引用 ID 有效，并不代表内容支持答案。
- 先以 5 份报告 / 5 道问题完成运行与错误排查，再准备有真值的评测；功能闭环不等于泛化准确率。
